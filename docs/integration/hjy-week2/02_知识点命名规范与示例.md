# 02 知识点库命名规范与示例

## 1. 统一使用锁定版知识点

所有后续生成、校验、组卷和检索，都必须使用下面这个锁定版词表：

- `outputs_fixed/408_data_v2/408_knowledge_points_final_v1_locked.jsonl`
- `outputs_fixed/408_data_v2/408_knowledge_points_final_v1_locked.csv`

版本状态：`locked`

知识点总数：110

## 2. 知识点字段规范

| 字段 | 类型 | 说明 |
|---|---|---|
| `kp_id` | string | 统一知识点 ID，格式 `KP-三位数字`，例如 `KP-001` |
| `name` | string | 锁定词表中的统一知识点中文名称，例如 `时间复杂度分析` |
| `subject` | string | 所属课程 |
| `importance` | string | `high`、`medium`、`low` |
| `bloom_level` | string | 认知层级 |
| `prerequisites` | array[string] | 前置知识点名称列表 |
| `lock_status` | string | 固定为 `locked` |
| `decision` | string | 固定为 `accept` |

## 3. 命名规则

1. 统一使用中文知识点名称，不使用网页原始标签。
2. 知识点 ID 只使用 `KP-001` 到 `KP-110`，不要临时新增。
3. 同一个知识点只保留一个规范名。
4. 生成题目时，`MCQuestion.knowledge_point` 使用知识点中文名；在题目记录里对应字段名通常写作 `kp_name`。
5. 校验和组卷时，如果需要唯一匹配，用 `kp_id`。
6. 如果一个题目有多个知识点，生成接口可以先填第一个主知识点；完整数组放在解析数据里。

```python
import json

with open("408_knowledge_points_final_v1_locked.jsonl", encoding="utf-8") as f:
    knowledge_points = [json.loads(line) for line in f if line.strip()]

kp_by_id = {item["kp_id"]: item for item in knowledge_points}
kp_by_name = {item["name"]: item for item in knowledge_points}
```

## 6. 对接规则

### 生成接口输入

```json
{
  "knowledge_points": ["时间复杂度分析", "单链表基本操作"]
}
```

### 校验接口内部处理

1. 输入的知识点中文名如果字段叫 `kp_name`，先与锁定词表的 `name` 匹配，再找到唯一 `kp_id`。
2. 校验该知识点是否属于对应 `subject`。
3. 生成记录中同时保留 `kp_id` 和 `kp_name`；`kp_name` 必须等于锁定词表中的 `name`。

### 组卷接口输入

```json
{
  "knowledge_scope": [
    "时间复杂度分析",
    "单链表基本操作",
    "栈与队列"
  ]
}
```

## 7. 原始标签到规范知识点

原始网页标签不直接作为知识点使用，必须通过映射表转换为规范知识点。

映射文件：

`outputs_fixed/408_data_v2/408_tag_to_kp_mapping_v2_2.csv`

示例：

| `web_tag` | `canonical_kp_id` | `canonical_kp_name` |
|---|---|---|
| `ARQ协议` | `KP-087` | `滑动窗口协议` |
| `B+树` | `KP-018` | `B树与B+树` |
| `Belady异常` | `KP-068` | `页面置换算法` |

## 8. 如果遇到新知识点

1. 本周不要直接新增知识点。
2. 先记录为 `candidate_kp`，写入待评审表。
3. 若只影响少量题目，可以先用相近的 `kp_id`。
4. 新知识点必须经过 S1 复审后，才能进入下一版词表。
