## 摘要

本文面向 408 计算机学科专业基础备考场景，研究如何从样例卷中学习整卷结构，并在知识点、题型、分值、难度和 Bloom 层级约束下生成可验证的候选题目，进而完成约束组卷与个性化模考。系统构建“样例卷解析—试卷蓝图—知识增强生成—自动验证—冷启动难度校准—教师审核—约束组卷”的闭环。实验将从结构匹配、题目有效性、知识覆盖、干扰项质量、难度相关性和教师接受度等方面评价系统。

**关键词：** 自动题目生成；教育 NLP；试卷蓝图；检索增强生成；误解建模；IRT；约束组卷

## 1. 引言

### 1.1 研究背景

408 复习需要覆盖数据结构、计算机组成原理、操作系统、计算机网络四门课程，题目数量多、知识依赖复杂，学生也存在明显薄弱点和个体差异。现有真题资源主要以整卷、年份或知识点浏览为主，个性化练习仍依赖学习者自行筛选。

本段补充：当前公开 408 真题浏览与练习方式的基本现状；不直接复制或公开受限内容。

### 1.2 问题与痛点

- 教师侧：人工出题耗时，整卷结构复用困难，知识点覆盖和难度梯度难以同时约束。
- 学生侧：优质练习数量有限，错题与后续个性化练习之间缺少可追踪链路。
- 技术侧：直接调用大模型生成题目容易产生事实错误、答案多解、知识点偏离和重复。

### 1.3 研究问题

- **RQ1：** 能否从样例卷中有效学习题型比例、分值结构、知识点覆盖和难度梯度，并用于约束生成？
- **RQ2：** 如何在生成与验证环节降低答案错误、知识偏离和多解题目的比例？
- **RQ3：** 在无大规模真实作答数据的冷启动场景下，如何估计题目难度并保持与教师判断的相关性？
- **RQ4：** 将上述模块组合为教师可审核、学生可使用的闭环后，系统能否在结构、质量和可用性上达到一期目标？

### 1.4 主要贡献

1. 提出面向 408 的样例卷蓝图表示与结构约束方法。〔待实验支持〕
2. 构建融合规则校验、语义查重、知识约束和代码测试的多维验证流程。〔待实验支持〕
3. 探索误解标签驱动的干扰项生成与模拟学生+IRT 冷启动难度估计的组合。〔待实验支持〕
4. 实现可演示的教师审核、约束组卷和学生个性化模考系统。〔待完成〕

贡献表述必须以最终实验证据为准，不能把“已设计”写成“已验证有效”。

## 2. 相关工作

### 2.3 误解建模与干扰项生成

讨论 DiVERT、Feng 等工作如何利用误解或错误信息生成干扰项，以及本项目扩展到计算机课程误解标签库的差异。

### 2.4 难度估计与教育测量

### 2.5 自动组卷与约束优化

### 2.6 研究空白

相关研究通常只覆盖“单题生成”“干扰项生成”或“难度预测”中的一个模块，缺少整卷结构约束、自动验证、冷启动校准和教师介入的统一闭环。本文尝试在 408 单课程场景中验证该闭环的最小可行实现。

## 3. 问题定义

### 3.1 输入与输出

| 对象 | 定义 |
|---|---|
| 样例卷集合 | \(P=\{p_1,\ldots,p_n\}\)，含题目、题型、分值、知识点和可获得的难度线索 |
| 课程知识结构 | \(G=(V,E)\)，节点为知识点，边为依赖关系 |
| 误解标签 | \(M=\{m_1,\ldots,m_k\}\)，包含误解描述与对应知识点 |
| 蓝图 | \(B=(B_{type},B_{score},B_{topic},B_{difficulty},B_{bloom})\) |
| 生成题目 | \(q=(stem,options,answer,rationale,topic,bloom,difficulty,source)\) |
| 组卷结果 | 满足硬约束、尽量优化软约束的题目集合 \(Q\) |

### 3.2 约束

- 硬约束：总分、题量、题型、指定知识点、必需分科、答案有效性。
- 软约束：难度分布、知识点均衡、误解多样性、个性化权重。
- 阻断规则：答案错误、严重重复、隐私或安全风险不得进入发布试卷。

### 3.3 评价问题

将系统视为同时产生题目内容和整卷结构的受控生成系统，分别评价单题有效性、整卷结构一致性和用户体验。教育效果不在本期作因果结论。

## 4. 方法

### 4.1 总体架构

建议插图：系统总体架构图。  
建议标注：输入层、Agent 层、证据层、教师审核层、输出层。

### 4.2 样例卷解析与蓝图学习

说明 DOCX/PDF 文本抽取、题目切分、题型识别、分值和知识点映射方法。区分“直接识别”“规则推断”“模型估计”“教师确认”四种来源。

蓝图匹配度：

\[
S_{\text{dist}}(p,q)=1-\frac{1}{2}\sum_i |p_i-q_i|
\]

\[
B_{\text{match}}=0.40S_{\text{type}}+0.30S_{\text{score}}+0.20S_{\text{knowledge}}+0.10S_{\text{difficulty}}
\]

说明各权重设定理由，并在消融实验中报告不同权重下的敏感性分析。

### 4.3 知识与误解约束

说明 408 四科知识图谱、知识点粒度、依赖关系、误解标签结构和检索方式。每条检索证据需要保存来源、片段和版本。

### 4.4 受控题目生成

描述 Prompt 结构、输入约束、输出 Schema、模型调用、重试和 Token 记录。区分选择题和算法/综合题模板。

### 4.5 多维度自动验证

至少包含：

- JSON Schema；
- 答案唯一性与解析一致性；
- 题干和选项冲突；
- 知识点命中；
- 语义重复检测；
- 算法题代码沙箱与测试用例；
- 低置信度题目路由到人工审核。

### 4.6 冷启动难度校准

说明模拟学生分层、作答生成、IRT 参数估计、教师标注校准和置信度。若样本量不足，必须将结论限定为探索性。

### 4.7 约束组卷与个性化

定义组卷目标函数、硬/软约束、不可满足时的降级策略，以及薄弱点权重的来源。输出必须包含组卷依据和随机种子，保证可复现。

### 4.8 教师审核与可追溯性

说明模型版本、Prompt 版本、检索证据、自动验证结果、教师决定和导出记录如何关联。教师审核不应被自动验证结果替代。

## 5. 系统实现

### 5.1 技术栈

后端第一周已冻结 FastAPI、Pydantic、统一 LLM Client、日志组件和五个 Agent 契约接口。前端原型为原生 HTML/CSS/JavaScript，后续通过统一 `BaseResponse` 对接。向量库、数据库和部署方式待后续阶段确定。

### 5.2 核心数据结构

当前 Schema 包含：

- `ExamBlueprint`：整卷题型比例、知识范围、难度分布和时长；
- `MCQuestion`：选择题题干、选项、答案、知识点、难度、Bloom 层级、误解标签和解析；
- `ValidationReport`：Schema、答案唯一性、语义重复、知识点匹配和置信度；
- `DifficultyParams`：IRT 难度、区分度、猜测率和预测正确率；
- `ExamPaper`：组卷后的题目、覆盖率和平均难度。

当前限制：408 综合/算法题尚未有独立结构；`MCQuestion` 不支持多个知识点、多个误解标签和单题分值。正式实验前需要冻结兼容版本，避免不同模块私自扩字段。

### 5.3 教师端

上传样例卷、蓝图确认、生成验证、题目审核、组卷和导出。第一周已接入接口路径 `/api/exam/parse`、`/api/question/generate`、`/api/question/validate`、`/api/question/calibrate` 和 `/api/paper/compose` 的契约；业务接口仍为预留桩。

- 报告生成失败、超时和被排除样本数量。

## 9. 局限性与伦理

- 主要验证限于 408 单课程，不能直接外推到其他学科。
- 样例卷数量有限，蓝图字段可能受版式和标注质量影响。
- 模拟学生与真实学生分布存在偏差，IRT 参数只作探索性估计。
- 教师评审规模有限，可能存在个人评分偏好。
- 生成模型可能产生事实错误、偏见或数据泄漏风险，因此必须保留人工审核。
- 仅使用公开或获授权材料，个人作答数据匿名化并最小化采集。

## 10. 结论与展望

总结系统是否实现“生成—验证—校准—组卷”闭环，以及实验支持的结论。未来工作包括：真实作答数据积累、复杂扫描件 OCR、跨课程知识迁移、更严格的代码沙箱和更大规模教学评估。
