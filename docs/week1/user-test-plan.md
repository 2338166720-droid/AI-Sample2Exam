# AI-Sample2Exam 408 方向用户测试流程

版本：第一周初稿  
目标：在系统尚未完全联调前，先验证教师能否完成出卷任务、学生能否完成模考任务，以及关键结果是否可理解。本方案用于可用性测试和小规模教学评价，不用于高利害考试。

## 1. 测试目标

本轮测试回答四个问题：

1. 教师能否独立完成“上传样例卷→确认蓝图→生成→审核→组卷→导出”。
2. 教师是否理解自动验证证据，并能做出可追踪的通过/修改/拒绝决定。
3. 学生能否完成模考、理解成绩构成，并知道下一步练什么。
4. 哪些页面、状态或文案会造成阻断性错误。

本轮不回答“系统已经达到稳定教育测量精度”。IRT、难度相关性和教学效果需要更大样本的后续实验。

## 2. 参与者

### 2.1 最低样本

| 对象 | 预测试 | 第一轮正式测试 |
|---|---:|---:|
| 熟悉 408 的教师或助教 | 1 | 2—3 |
| 正在备考 408 的学生 | 2 | 5—8 |

预测试用于发现流程问题；修改阻断性缺陷后再做正式测试。若教师人数不足，可邀请熟悉 408 原理课的研究生助教，但报告中必须如实说明身份。

### 2.2 招募条件

- 教师：教授或辅导过数据结构、计算机组成原理、操作系统、计算机网络中的至少一门。
- 学生：正在备考 408 或完成过相关课程，能独立使用浏览器。
- 排除条件：项目组成员、看过系统内部 Prompt 或已参与原型设计者，不应计入独立用户测试样本。
- 自愿参加，可随时停止；不收集与测试无关的学号、电话、身份证号等信息。

## 3. 测试环境

- Windows 11 电脑，Chrome 或 Edge 最新稳定版。
- 屏幕分辨率不低于 1366×768；若使用 1920×1080 更接近实际演示环境。
- 原型本地打开，不需要联网；正式联调版需准备备用演示数据，避免网络失败阻断。
- 录音或录屏必须单独征得同意。默认只记录匿名观察笔记。
- 测试开始前清除前一参与者的本地状态，使用新的浏览器无痕窗口。

## 4. 角色分工

| 角色 | 职责 |
|---|---|
| 主持人 | 读任务脚本、控制节奏，不提示具体点击位置 |
| 观察员 | 记录完成情况、时间、错误和建议，不参与指导 |
| 技术支持 | 处理崩溃或数据重置，故障不计入用户操作错误 |
| 参与者 | 按自然方式完成任务并表达真实困惑 |

至少两人参与每场测试；只有主持人时，应在结束后立即补写观察记录。

## 5. 时长与议程

每场建议 45—55 分钟。

| 时间 | 环节 | 内容 |
|---:|---|---|
| 0—5 分钟 | 介绍与知情同意 | 说明目的、录音规则、可随时退出 |
| 5—10 分钟 | 背景访谈 | 日常出卷/模考方式、熟悉工具 |
| 10—35 分钟 | 教师或学生任务 | 主持人不直接指点，必要时标注“协助完成” |
| 35—45 分钟 | 复盘访谈 | 追问困惑、信任度、最想修改之处 |
| 45—50 分钟 | 问卷与结束 | 满意度简表、数据确认、致谢 |

## 6. 开场说明

主持人可逐字使用：

> 今天测试的是系统原型，不是你。我们想了解哪些地方让人困惑或难以信任，不会评价你的能力。请尽量按平时习惯完成任务，并说出你正在寻找什么、为什么这样操作。遇到不知道下一步时，可以告诉我，不需要勉强猜测。测试内容只用于课程项目改进，报告会使用匿名编号。

不要使用“这里应该点这个”“这个按钮就是下一步”等操作性提示。参与者确实卡住时，记录卡住时间和原因，再决定是否给予最低限度帮助。

## 7. 教师测试任务

### T-0 背景访谈

1. 你通常如何整理一套 408 练习卷？
2. 判断一道选择题能否使用时，你最看重什么？
3. 你过去是否使用过自动出题或智能组卷工具？哪些结果让你不信任？

### T-1 上传并检查样例卷

任务：上传演示样例卷，完成解析并进入蓝图确认页。

成功标准：

- 找到上传入口；
- 完成解析；
- 能说出总题量、总分、四科分布中至少两项；
- 能识别哪些字段是“推断值”或“待确认”。

记录：完成/协助完成/未完成、耗时、误点、是否理解下一步。

### T-2 设置整卷约束

任务：把简单/中等/困难题目比例设置为 30/50/20，并把“外部排序”加入重点知识点。

成功标准：

- 找到可编辑的蓝图字段；
- 完成修改并知道是否保存成功；
- 能解释选择这些约束的目的。

故意设置的观察点：若比例总和不为 100%，系统能否给出明确反馈。

### T-3 审核题目

任务：系统预置 1 道答案正确题、1 道歧义题和 1 道知识点偏题。请分别作出通过、修改、拒绝决定。

成功标准：

- 能找到验证证据和原题解析；
- 拒绝时能填写原因；
- 不把“自动验证通过”误认为教师已经批准；
- 能说明至少一条与系统自动判断不同的理由。

### T-4 组卷并处理约束冲突

任务：生成一份 408 个性化模考卷，使系统报告缺 1 道外部排序题、少 1 道困难题。

成功标准：

- 能解释未满足项；
- 会使用“自动建议替换”或调整约束；
- 知道成功替换了哪道题；
- 能判断是否仍有发布阻断项。

### T-5 导出与发布检查

任务：下载 JSON，并打印或另存为 PDF。

成功标准：

- 能区分“仅题目版”和“答案版”；
- 知道导出文件对应哪次组卷；
- 检查导出前没有泄露答案到学生版；
- 能完成或判断是否需要进入正式发布。

## 8. 学生测试任务

### S-0 背景访谈

1. 你通常怎样选择下一套 408 练习？
2. 看到模考成绩后，你最希望系统告诉你什么？
3. 哪些个性化推荐会让你觉得有帮助，哪些会让你觉得被过度推断？

### S-1 开始模考

任务：从首页选择“薄弱点练习”并开始 3 道演示题。

成功标准：

- 找到推荐入口；
- 理解预计题量和时长；
- 不需要开发者解释即可开始。

### S-2 作答与提交

任务：完成 2 道题，第 3 道留空，尝试提交。

成功标准：

- 已答/未答状态清晰；
- 计时器可见且不干扰；
- 未答时出现确认，能返回补答；
- 可成功提交。

### S-3 阅读结果

任务：说明自己得了多少分、哪一科较弱、系统建议下一步做什么。

成功标准：

- 正确解释得分构成；
- 能找出至少一条薄弱点证据；
- 能说明预测难度与真实得分的区别；
- 能发起下一次针对性练习。

### 问题严重度

| 等级 | 定义 | 处理 |
|---|---|---|
| P0 阻断 | 无法继续、数据错误、答案误发、隐私泄露 | 当轮修复后重新验证 |
| P1 严重 | 需要帮助才能完成核心任务，或明显误解验证结果 | 第一轮正式测试前修复 |
| P2 一般 | 可完成任务但效率低、文案不清或状态不明确 | 按影响排序迭代 |
| P3 轻微 | 不影响任务完成的视觉或措辞问题 | 有余量时修复 |

## 10. 复盘访谈

### 教师

1. 你最信任和不信任页面上的哪一项信息？为什么？
2. 如果系统通过了一道答案错误的题，你希望界面怎样提醒？
3. 组卷冲突时，系统给出“失败”和“最接近方案”，你更希望看到哪种？请说明。
4. 这份试卷的导出结果是否符合你实际出卷习惯？
5. 如果下周必须用它出一套练习卷，你还缺少什么？

### 学生

1. 你能否说清这个分数是如何得到的？
2. “薄弱点”的依据是否足够让你相信？还需要什么证据？
3. 结果页是否让你知道下一步该练什么？
4. 哪一项信息让你觉得系统在夸大能力或过度推断？
5. 你愿意用这套系统做一次完整 408 模考吗？为什么？

## 11. 简版体验问卷

采用 5 级量表：1=非常不同意，5=非常同意。

| 题项 | 1 | 2 | 3 | 4 | 5 |
|---|---:|---:|---:|---:|---:|
| 我能理解系统的主要工作流程 | □ | □ | □ | □ | □ |
| 系统清楚区分了自动验证与教师决定 | □ | □ | □ | □ | □ |
| 我能看懂组卷未满足的约束 | □ | □ | □ | □ | □ |
| 结果页提供了可执行的下一步建议 | □ | □ | □ | □ | □ |
| 系统没有对单次结果作过度推断 | □ | □ | □ | □ | □ |
| 我愿意在真实学习或出卷中继续使用 | □ | □ | □ | □ | □ |
| 页面整体操作负担可以接受 | □ | □ | □ | □ | □ |

另记录一个 0—10 分的总体推荐意愿（NPS 风格，仅作辅助）：

> 你有多大可能把此原型推荐给同样备考 408 或需要出练习题的人？

## 12. 数据整理与验收

### 12.1 定量

- 任务完成率 = 独立或协助完成的任务数 / 应完成任务数。
- 独立完成率 = 无提示完成任务数 / 应完成任务数。
- 平均任务时间：只统计完成任务的样本，并同时报告中位数。
- 阻断错误数：导致无法继续的错误次数。
- 理解正确率：参与者对得分、薄弱点依据、下一步建议三项解释正确的比例。
- 体验均分：各题项均值、标准差和样本量。

### 12.2 定性

将观察和访谈编码为：

- 流程导航；
- 状态反馈；
- 质量与信任；
- 难度与个性化解释；
- 导出与发布；
- 数据与隐私；
- 性能稳定性；
- 功能缺失。

每个问题记录证据、严重度、影响人数和建议修复版本，不只保留主观印象。

### 12.3 第一轮验收门槛

- 无 P0 问题；
- 教师核心任务独立完成率 ≥ 80%；
- 学生核心任务独立完成率 ≥ 80%；
- 结果三项关键信息理解正确率 ≥ 80%；
- 完整教师演示流程无阻断，P95 耗时符合指标表；
- 所有拒绝、发布和导出动作都有可追溯记录。

未达到门槛时，先修正流程和状态表达，不使用“用户不熟练”作为唯一解释。测试人数较小时，结果只作形成性反馈，不作统计学显著性结论。

## 13. 测试前检查清单

- [ ] 使用匿名编号，未采集无关个人信息。
- [ ] 录音、录屏已获得明确同意。
- [ ] 浏览器、打印、下载和备用数据均已检查。
- [ ] 自动验证结果没有在教师盲评前提前泄露。
- [ ] 演示题不包含未经授权的题库材料。
- [ ] P0 问题有单独记录和即时停止机制。
- [ ] 测试后保存观察记录、问卷和系统日志，并核对编号一致。
