# AI-Sample2Exam（408 方向）需求与页面流程

版本：第一周初稿  
负责人：陈星洁  
目标：在不依赖其他成员模块产出时，先冻结教师端、学生端最小流程，为后续联调提供统一页面与状态定义。

## 1. 一期目标

系统需要形成一条可演示、可检查的闭环：

> 上传 408 样例卷 → 提取试卷蓝图 → 按知识点与结构约束生成题目 → 自动验证 → 教师审核 → 约束组卷 → 导出试卷 → 学生模考 → 查看薄弱点报告

一期只覆盖：

- 选择题；
- 算法设计题；
- 408 综合应用题；
- 文本型 Word/PDF 样例卷；
- 单机 Demo，不追求高并发和完整账号体系。

复杂扫描件 OCR、跨课程泛化、正式在线判题平台和高并发部署不作为一期验收条件。

## 2. 角色与核心需求

### 2.1 教师

| 需求 | 最小实现 |
|---|---|
| 上传样例卷 | 支持选择一个 DOCX/PDF，显示文件名、大小、解析进度 |
| 检查蓝图 | 展示题量、总分、四科分布、题型比例、知识点和难度梯度 |
| 设置生成条件 | 科目、知识点、题型、题量、难度和 Bloom 层级 |
| 审核题目 | 通过、退回修改、拒绝，并记录原因 |
| 组卷 | 约束总分、题量、题型比例、知识点覆盖和难度 |
| 导出 | 试卷、答案与解析、结构化 JSON、难度报告 |

### 2.2 学生

| 需求 | 最小实现 |
|---|---|
| 开始模考 | 选择整卷、薄弱点或错题相关练习 |
| 作答 | 查看计时、题号、答题状态，提交选择题答案 |
| 查看结果 | 总分、分科得分、知识点表现和逐题解析 |
| 继续练习 | 依据薄弱知识点发起个性化练习 |

## 3. 页面流程

### 3.1 教师端

```text
工作台
  └─ 上传样例卷
      └─ 解析结果
          └─ 确认试卷蓝图
              └─ 设置生成约束
                  └─ 候选题目与自动验证
                      ├─ 校验失败 ──> 重新生成/退出
                      └─ 校验通过
                          └─ 人工审核
                              ├─ 退回 ──> 生成或人工编辑
                              └─ 通过
                                  └─ 约束组卷
                                      └─ 整卷结构检查
                                          ├─ 不满足 ──> 调整约束/替换题目
                                          └─ 满足
                                              └─ 导出与发布
```

### 3.2 学生端

```text
学习首页
  ├─ 整卷模考
  ├─ 薄弱知识点练习
  └─ 错题相关练习
      └─ 答题与自动保存
          └─ 提交
              └─ 成绩与知识点报告
                  └─ 发起下一轮个性化练习
```

## 4. 页面级需求

### P01 教师工作台

- 显示当前课程、样例卷数量、候选题目数、待审核数、已组卷数和最近实验状态。
- 提供唯一的主动作“上传样例卷”。
- 最近项目显示状态：解析中、待确认、生成中、待审核、已组卷、已发布。

验收点：第一次使用者能在 30 秒内找到上传入口并理解下一步。

### P02 上传与解析

- 接受 `.docx`、`.pdf`，大小上限可暂定 20 MB。
- 显示上传、解析、切题、蓝图提取四个阶段的进度。
- 解析完成后先展示结构化摘要，不直接跳入生成。
- 对无法识别的字段明确标记“待人工确认”，不静默猜测。

验收点：任何解析失败都能显示失败阶段、原因和可执行操作。

### P03 蓝图确认

- 顶部显示样例卷年份、题量、总分和预计时长。
- 展示四科题目数和分值分布。
- 展示题型比例及难度梯度；原卷缺少可核验难度时必须标记“推断值”。
- 允许教师修改分科数量、题型比例、重点知识点和难度上限。
- 保存前后均显示“未保存修改”提示。

建议的蓝图视图字段：

| 字段 | 示例 | 来源状态 |
|---|---|---|
| 课程 | 408 计算机学科专业基础 | 固定 |
| 样例卷 | 408 通用结构演示卷（自拟） | 演示 |
| 总分 | 150 | 已识别 |
| 题量 | 47 | 已识别 |
| 预计时长 | 180 分钟 | 已识别/人工确认 |
| 科目分布 | DS 13、CO 13、OS 12、CN 9 | 已识别 |
| 题型分布 | 选择题 40、综合应用题 7 | 已识别 |
| 难度分布 | 易 30%、中 50%、难 20% | 推断，待审核 |
| 知识点覆盖 | 按 408 四科考纲映射 | 待知识库接入 |

字段名称以后由题目 Schema 负责人确认，当前仅约束页面所需信息。

### P04 生成与自动验证

- 生成参数采用分步表单，避免一次展示过多字段。
- 自动验证至少展示：Schema、答案一致性、重复率、知识点匹配、代码/测试用例、难度置信度。
- 每个失败项给出原因、证据和建议动作。
- 当题目被自动判定低置信度时，必须进入人工审核，不可直接发布。

验收点：用户能区分“生成失败”“验证失败”“人工拒绝”三种情况。

### P05 人工审核

- 支持按科目、题型、状态、验证结果筛选。
- 单题详情同时显示题干、选项、答案、解析、知识点、Bloom 层级、难度、来源与验证证据。
- 审核动作：通过、退回修改、拒绝。
- 拒绝必须选择原因，可选“答案错误、题意不清、多解、重复、知识点偏离、难度不符、其他”。
- 显示审核人和审核时间，便于实验统计。

### P06 约束组卷

- 输入：总分、题量、题型比例、四科/知识点覆盖、难度分布、个性化权重。
- 输出：满足约束的题目清单和结构检查报告。
- 当无法完全满足约束时，展示最接近方案及未满足项，禁止只报“失败”。
- 个性化练习需展示加权原因，例如“因二叉树遍历错误率 62%，该知识点权重提高”。

### P07 试卷与导出

- 试卷预览使用接近打印稿的版式。
- 仅题目版和答案版分开导出，避免误发答案。
- 至少提供浏览器打印/PDF 与 JSON 下载；DOCX 作为后端接入后的增强项。
- 导出文件包含随机组卷 ID，便于实验追踪。

### P08 学生学习首页

- 提供三个入口：整卷模考、薄弱知识点、错题相关练习。
- 显示最近一次诊断的知识点，不展示未经真实作答支持的诊断。
- 首次使用可跳过诊断，选择“直接模考”。

### P09 答题页

- 固定显示计时、题号、已答/未答、提交按钮。
- 选择题支持选项选择、标记待检查；算法/综合题一期只支持文本或图片占位。
- 离开页面前提示；自动保存当前答案。

### P10 结果页

- 顶部展示总分、用时、分科正确率。
- 中部展示知识点掌握情况与错误归因。
- 底部提供逐题解析和“针对薄弱点再练一练”。
- 预测难度、模拟学生结果需标记为模型估计，不作为真实考生排名。

## 5. 核心状态

### 5.1 样例卷状态

`uploaded → parsing → parsed → blueprint_confirmed → archived`

失败状态：`parse_failed`。

### 5.2 题目状态

`draft → generated → validating → auto_validated → pending_review → approved / rejected`

低置信度附加标记：`needs_human_review`。

### 5.3 试卷状态

`draft → assembling → assembled → checked → published → archived`

## 6. 408 专项约束

- 四科比例可配置，但结构检查必须分别报告每科结果。
- 选择题默认 2 分，综合应用题分值从蓝图读取，不写死。
- 算法设计题需要记录语言、时间/空间复杂度、参考实现、测试用例和判题限制。
- 计算机组成原理、操作系统、计算机网络题目优先检查术语一致性、单位、图表引用和计算条件是否完整。
- 知识点必须落到考纲可追踪节点，不能只使用“数据结构”这类过粗标签。
- 个性化难度不得以“越难越好”为目标，应匹配学生的最近发展区和教师设定。

## 7. 页面验收清单

- [ ] 教师能从工作台完成上传、确认、生成、审核、组卷、导出全流程。
- [ ] 学生能从首页完成一轮模考并看到知识点报告。
- [ ] 所有异步任务都有加载、成功、空、失败四种状态。
- [ ] 所有数值明确区分“识别值、推断值、模型估计、真实作答”。
- [ ] 审核、组卷和导出操作可追溯到来源与版本。
- [ ] 演示内容不包含未经授权的题库材料。
- [ ] 页面文案能让首次使用者理解下一步，不依赖开发者口头解释。

## 8. 后端契约同步

2026-11-22 已根据 `feature/dyh-llm` 分支的接口契约同步页面数据：

| 页面动作 | 后端接口 | 当前状态 |
|---|---|---|
| 上传样例卷并解析 | `POST /api/exam/parse` | 契约存在，返回开发中桩 |
| 生成候选题目 | `POST /api/question/generate` | 契约存在，返回开发中桩 |
| 单题自动验证 | `POST /api/question/validate` | 契约存在，返回开发中桩 |
| 难度校准 | `POST /api/question/calibrate` | 契约存在，返回开发中桩 |
| 约束组卷 | `POST /api/paper/compose` | 契约存在，返回开发中桩 |

前端以 `BaseResponse.success` 判断成功，不在 `data` 为空时推断成功。页面中的题目对象遵循 `MCQuestion`；科目名称、分值和审核状态作为独立展示元数据，不写入题目模型。

当前待评审：

- `BaseResponse` 没有错误码字段；
- FastAPI 尚未配置 CORS 或静态前端托管；
- 408 综合/算法题无法由当前 `MCQuestion` 完整表达；
- 试卷蓝图缺少四科分布和各题型分值字段。

详细映射和兼容处理见 `07_后端接口对接说明.md`。
